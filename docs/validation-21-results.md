# 第二轮验证结果：21 个独立案例 × 3 次重复 × 5 组

完成日期：2026-09-20。实验范围：真实 DeepSeek LLM、合成业务事件、有状态本地模拟工具。本轮保持已有四项改进不变，只扩展验证规模。

315/315 组运行全部完成，共 1,890 个事件，没有预算中断或剔除案例。B3 在 21 个案例的三次重复中全部通过（63/63）；原始请求、结果汇总、数据与代码快照一致性审计通过。

## 1. 实验设置和比较口径

- 七类冻结测试场景各取 3 个案例，共 21 个独立案例；每例 6 个事件，每例重复 3 次。
- B0：修正后的固定流程；B1：按需路由、跨轮次去重与观察等待；B2：进一步加入读取复用；B3：进一步加入选择性记忆；M-Full：以完整有效历史替代 B3 的选择性历史。
- 模型 `deepseek-flash`，temperature=0，thinking_mode=disabled，输出上限 1,200 Token；组别交错执行。
- 仅测试 warm 条件：同一案例内允许跨事件复用；组间、案例间、重复运行间独立初始化环境、记忆与缓存。
- 统计独立单位是 21 个案例，三次重复留在同一案例簇内。配对 Bootstrap 重采样 1,000 次，报告 95% 置信区间。
- 所有组共用动作校验和幂等保护。错误原始提案即使被执行器拦截，仍影响质量评价。

预设方案见 [validation-21-protocol.md](validation-21-protocol.md)，配置见 [deepseek-validation-21.json](../configs/deepseek-validation-21.json)。本轮与第一轮开发集 pilot 分开统计。

## 2. 主要结果

| Agent 执行次数 | 1,890 | 858 | 858 | 810 | 810 |
| 真实 LLM 请求数（含失败与重试） | 1,116 | 196 | 195 | 171 | 171 |
| 后端读取请求数 | 3,024 | 675 | 414 | 414 | 414 |
| 后端写请求数 | 918 | 471 | 471 | 513 | 513 |
| 读取缓存命中次数 | 0 | 0 | 189 | 189 | 189 |
| 已知输入 Token | 257,280 | 41,358 | 41,358 | 76,611 | 157,161 |
| 已知输出 Token | 239,509 | 42,321 | 42,012 | 37,512 | 37,441 |
| 必要分支完成 / 应完成 | 378/378 | 378/378 | 378/378 | 378/378 | 378/378 |
| 重复决策 / 决策机会 | 231/396 | 0/222 | 0/222 | 0/198 | 0/198 |
| 重复执行次数 | 0 | 0 | 0 | 0 | 0 |
| 被拦截的动作提案数 | 45 | 45 | 45 | 0 | 0 |

B1 多出一次失败请求，重试后成功。B1 与 B2 的模型请求差 1 次来自该传输故障，不能归因于工具复用。

| 主要比较 | 点估计 | 按案例聚类的 95% CI | 目标判断 |
|---|---:|---:|---|
| B0 → B1：LLM 请求下降 | 82.4% | 75.7%～88.5% | 超过 30% 目标 |
| B1 → B2：后端读取下降 | 38.7% | 30.4%～46.4% | 有改善，未达 50% 目标 |
| M-Full → B3：输入 Token 下降 | 51.3% | 0.0%～64.6% | 点估计超过 40%，稳定结论证据不足 |
| B0 → B3：成功率差值 | +85.7 个百分点 | +66.7～+100.0 个百分点 | 本样本未出现质量下降 |

整体 B0 → B3 的 LLM 请求下降 **84.7%**，P95 耗时下降 **59.8%**。P95 是描述性点估计，本报告未为 P95 计算置信区间。这些整体收益由多项机制共同产生，不能全部记在单一优化名下。

所有组必要分支召回率均为 378/378。B0 的低成功率主要来自重复事件、观察期内仍提出禁止或不必要的动作，以及缺失历史约束；并不表示它没有执行必要分支，更不表示真实广告收益下降。

## 3. 已有四项改进分别说明什么

### 按需执行

B0 → B1 的 Agent 执行从 1,890 降至 858，模型请求从 1,116 降至 196，必要分支覆盖保持完整。说明在这些包含稳定状态、重复事件和明确任务的场景中，固定流程确实有大量可避免工作。

该对照同时启用了路由、同证据复用与观察等待，不能把 82.4% 精确拆分为每项机制的独立贡献。

### 跨轮次去重与观察等待

B0 记录 231 次重复决策，B1/B2/B3/M-Full 均为 0。系统能够识别没有新证据或仍在观察期的任务，减少重复提案。

所有组的重复实际执行均为 0，因为共用幂等执行器。此次结果支持“减少重复决策”，不能声称相对基线降低了重复执行率：基线该指标已经为零。

### 工具复用

B1 → B2 后端读取从 675 降至 414，成功率同为 54/63。批量读取和精确缓存减少了真实到达模拟后端的查询，质量没有下降。

38.7% 低于预设 50% 目标，保留该结果。缓存命中和批量合并都会影响读取数，因此不能将减少的 261 次读取全部称为缓存命中。此次串行工作流实验也不单独证明并发请求合并的收益；该能力由专项测试覆盖。

B2 的 P95 比 B1 略高，不能据此声称读取复用已带来稳定的端到端提速。真实模型耗时占据大部分时间，本地 SQLite 的查询节省并不等于生产广告 API 的耗时节省。

### 选择性记忆与上下文管理

历史约束类共 3 个独立案例、每例重复 3 次：

| 历史约束类指标 | B2（无历史） | B3（选择性） | M-Full（完整历史） |
|---|---:|---:|---:|
| 成功运行 | 0/9 | 9/9 | 9/9 |
| 原始输出约束通过 / 检查次数 | 57/102 | 54/54 | 54/54 |
| LLM 请求 | 51 | 27 | 27 |
| 输入 Token | 9,945 | 28,251 | 108,801 |
| 被拦截的动作提案 | 45 | 0 | 0 |

选择性记忆让模型获得有效历史约束，改善这些多轮案例的完成质量。它比无记忆消耗更多输入 Token，这是必要信息的成本；与完整历史相比，历史约束类输入减少 74.0%，全场景合计减少 51.3%，两组均通过 63/63。

不同组生成和检查的输出次数不同，因此约束检查分母不相等；同时报告分子、分母和案例成功率，不能只比较通过率。检查针对原始输出，执行器拦截不会被算成模型遵守了约束。

全场景 Token 节省的置信区间仍触及零，因为主要收益集中在仅 3 个记忆类独立案例。三次重复不能替代更多独立历史模式。B3 与 M-Full 的 P95 分别为 20.64 秒和 20.42 秒，本次不能声称选择性记忆比完整历史更快。本轮是历史随决策发展的端到端实验，未额外开展固定外部历史的记忆专项实验。

## 6. 可用于项目介绍的表述和边界

> 在 21 个独立合成业务案例、每例 3 次重复、5 组对照的真实 LLM 实验中，按需执行及跨轮次去重使模型请求较固定流程减少 82.4%；读取复用进一步减少后端读取 38.7%；选择性记忆较完整历史减少输入 Token 51.3%。最终系统在本轮 63 次运行中全部通过，必要分支完成 378/378，较固定流程整体减少模型请求 84.7%。

介绍时应同时说明：这是合成场景、单个模型、热缓存条件下的结果，21 个案例来自同一生成器与七类模板，63 次运行不是 63 个独立任务。记忆相关独立案例只有 3 个，Token 节省的总体置信区间仍触及零；工具读取未达最初 50% 目标。五个角色中主要由 Creative 调用真实 LLM，其余使用确定性实现。

本轮完成对现有四项机制的扩大验证，没有增加优化功能。未运行全量 210 案例、冷缓存或固定历史专项；本地 SQLite 和模拟执行结果不能外推到真实广告平台吞吐、费用、CTR、ROAS 或生产收益。
